# Worklog — 2026-08-16 22:15

## Summary
Bootstrapped the cimi dentist-office app from `mvp.md` into a running local dev pipeline: FastAPI backend, two independently-runnable Next.js frontends (desktop + a mobile-first web app), Docker Compose with profile-gated selection between them, non-Docker `utils/` tooling, a lint-only CI workflow, and a from-scratch mobile landing-page redesign built on supplied illustrations/icons matching a "Bright Smile" design comp. No business logic (data model, auth, booking) exists yet — this is infra/UI scaffolding only, tracked explicitly in `todo.md`.

## Details
- **Backend** (`backend/`): FastAPI app with `/health` (liveness), `/api/v1/hello` (hello-world wiring check), `/api/v1/status` (async SQLAlchemy + `redis.asyncio` connectivity check against Postgres/Redis). `Settings` via `pydantic-settings`, `CORS_ORIGINS` comma-parsed to a list, default widened to cover both frontend ports (`:3000`, `:3001`). No domain models, no auth, no versioned/admin API namespace yet.
- **Desktop frontend** (`frontend/`): Next.js 16 (App Router) + React 19 + Tailwind v4 + TypeScript. Route groups: `(public)` (Home/Services/Team/Gallery/About/Book/Login/Account) and `admin` (Dashboard/Appointments/Doctors/Services/Availability/Gallery/Audit Log) — two separate layout shells (`PublicNav` top nav vs. `AdminNav` sidebar), matching `mvp.md §5`'s site map almost exactly. All non-home routes are `PageStub` placeholders. Home page does a server-side fetch of `/api/v1/hello` and renders reachability inline.
- **Mobile frontend** (`frontend-mobile/`): separate Next.js app, patient-facing only (no admin surface — office staff assumed desktop). Bottom tab bar (`BottomNav.tsx`) + `TopBar.tsx` shell instead of the desktop nav; iOS safe-area CSS (`env(safe-area-inset-*)`), `appleWebApp` meta tags for Safari "Add to Home Screen", `app/manifest.ts` for Android/Chrome installability (real icon PNGs still a TODO in that file).
  - Landing page (`src/app/page.tsx`) redesigned around real assets copied from `frontend/photos/` into `public/`: hero illustration (`landing-hero.png`), a services quick-links grid (3 columns, 6 of the 16 available service icons — Преглед/Ендодонција/Импланти/Ортодонција/Вађење зуба/Дигитални RTG), a "why patients trust us" band (`landing-care.png`), and a CTA banner using the real `smile.png` icon instead of a hand-drawn one.
  - `icons.tsx`: removed `ToothIcon`/`SparklesIcon` (fully superseded by real `tooth-icon.png`/`instruments-icon.png`); added `CONTENT_ICON_SIZE`/`NAV_ICON_SIZE` shared constants so every icon on the page — real PNG or hand-drawn SVG fallback (`BellIcon`, `CalendarIcon`, `ShieldCheckIcon`, `HeartIcon`, `HomeIcon`, `GalleryIcon`, `UserIcon`, kept where no matching real asset exists) — renders at one of exactly two sizes instead of ad hoc values.
  - `BottomNav.tsx` shrunk ~20-25%: icons 16px→12px, elevated center "Заказивање" circle 56px→36px, padding trimmed to match; `layout.tsx`'s bottom clearance adjusted `pb-20`→`pb-16` accordingly.
  - Brand palette (`globals.css` `@theme`): consolidated CTA banner/button/nav to one `--color-brand` (#1656e0) instead of a separate darker fill; `--color-navy` (#0b1830) for headline text; `--color-brand-dark` now exists only for press/hover states.
- **Docker Compose** (`docker-compose.yml`): `frontend-desktop` (renamed from `frontend`) and `frontend-mobile` gated behind Compose `profiles: [desktop]` / `profiles: [mobile]` respectively — `backend`/`postgres`/`redis` have no profile and always start. Selected via `docker compose --profile desktop|mobile up`, either or both. Ports: desktop `3000:3000`, mobile `3001:3000`.
- **Non-Docker tooling** (`utils/`): `setup-backend-env.sh` auto-detects `conda` vs `venv` (override via `CIMI_ENV_TOOL`); `setup-frontend-env.sh`/`start-frontend.sh`/`start-all.sh` all take a `desktop|mobile|both` target argument. No install/start step runs without the user explicitly invoking the script — deliberate, per explicit instruction not to run installs autonomously.
- **CI** (`.github/workflows/validate.yml`): file-validity checks only, explicitly no unit tests, no build/deploy. `backend-validate`: `ruff check` + `python -m compileall`. `frontend-validate`: matrix over `[frontend, frontend-mobile]`, `eslint .` + `tsc --noEmit`. `compose-validate`: `docker compose config -q` after `cp .env.example .env`.
- **Docs**: `todo.md` — coverage of `mvp.md` by section, color-coded (🟢/🟡/🔴), with a callout for known gaps between working tree and committed state at the time it was written (now resolved — see below).

## Decisions / trade-offs
- Mobile app deliberately excludes `/admin` — office-staff tooling assumed desktop-only; not stated in `mvp.md`, which predates the desktop/mobile split.
- Feature row on the mobile landing page keeps hand-drawn `ShieldCheckIcon`/`HeartIcon` rather than forcing a real asset in — none of the 16 supplied dental-procedure icons semantically fit "expertise" or "atmosphere"; only "технологија" got a real-icon swap (`instruments-icon.png`), since that one actually fit.
- `landing-tools.png` (`frontend/photos/lending3.png`) was copied into `frontend-mobile/public/` but deliberately not placed on the landing page — three large illustrations on one mobile page was judged too heavy; earmarked for `/services` instead.
- CI intentionally has no unit tests and no deploy stage — explicit user scope decision, not an oversight; `mvp.md §13` describes a fuller pipeline for later.
